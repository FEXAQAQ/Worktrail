# Worktrail：安裝與解除說明

本手冊說明如何安裝、啟動、更新與移除 Worktrail。所有操作都可以用專案資料夾內的按鈕完成，不需要記指令。

## 1. 專案資料夾內的按鈕

| 檔案 | 用途 | 什麼時候用 |
| --- | --- | --- |
| `一鍵安裝.cmd`（Windows）／`一鍵安裝.command`（macOS） | 安裝或更新 Worktrail，缺少的 Node.js、Claude Code 會一併安裝 | 第一次安裝、更新程式後、搬移專案資料夾後 |
| `啟動 Worktrail`（安裝後才會出現） | 開啟 Worktrail 視窗 | 每天查看日誌、產生週報 |
| `一鍵解除安裝.cmd`／`一鍵解除安裝.command` | 移除所有設定，**保留日誌** | 不想再使用、或要暫停自動記錄 |

> Windows 雙擊 `.cmd` 若出現「Windows 已保護您的電腦」，按「其他資訊 → 仍要執行」。這是因為腳本沒有數位簽章。

## 2. 系統需求

- Windows 10／11（主要支援），或 macOS 13 以上
- Node.js 20 以上：沒有的話一鍵安裝會以 winget（Windows）或 Homebrew（macOS）安裝
- Claude Code：沒有的話一鍵安裝會以 `npm install -g @anthropic-ai/claude-code` 安裝。尚未登入 Claude 帳號時，一鍵安裝會直接開啟登入
- 網路：只有安裝時需要（下載 Node.js、Claude Code 與相依套件）。安裝完成後 Worktrail 本身不連網

## 3. 一鍵安裝

1. 雙擊專案資料夾內的 **`一鍵安裝.cmd`**（macOS：`一鍵安裝.command`）。
2. 視窗會依序執行五個步驟。只有要安裝 Node.js 或 Claude Code 時會詢問，其餘都用預設值：

| 步驟 | 做什麼 | 會詢問 |
| --- | --- | --- |
| 1. Node.js | 檢查版本，沒有或太舊時安裝 Node.js LTS | 是否安裝 |
| 2. Claude Code | 檢查 `claude` 指令，沒有時安裝；尚未登入時開啟登入 | 是否安裝（可略過，但 UI 的一鍵產生功能會無法使用） |
| 3. 建置 | 安裝相依套件、建置程式與啟動器（第一次約 1～3 分鐘） | — |
| 4. 安裝 Worktrail | 註冊到 Claude Code、建立捷徑、設定開機自動啟動；日誌存放在上次的資料夾，第一次為 `~/Worktrail`；服務在跑舊版時自動重啟 | —（資料夾與開機自動啟動可在 設定 → 儲存、設定 → 整合 更改） |
| 5. 開啟 | 開啟 Worktrail 視窗 | — |

3. 看到「安裝完成」後，**開啟一個新的 Claude Code 對話**，自動記錄才會生效（已開啟的對話不會被記錄）。

### 安裝會修改哪些地方

| 位置 | 內容 | 備份 |
| --- | --- | --- |
| `~/.claude/settings.json` | 加入 SessionStart、Stop、SessionEnd 三個 hook，以及權限 `mcp__worktrail__*`（讓 Claude 寫日誌時不必每次詢問） | 修改前備份為 `settings.json.worktrail-backup-<時間>` |
| Claude Code 的 MCP 設定（user scope） | 註冊 `worktrail` MCP Server | — |
| `~/.claude/commands/` | `/worklog`、`/worklog-weekly`、`/worklog-perf`、`/worklog-ui` 四個指令 | 不會覆寫你自己的同名檔案 |
| `~/.claude/CLAUDE.md` | 末尾加入一段以 `<!-- worktrail:start -->`／`<!-- worktrail:end -->` 包住的規則 | 修改前備份 |
| `~/.worktrail/` | 記錄日誌資料夾的位置、服務的連線資訊 | — |
| 桌面、開始功能表、專案資料夾 | 「Worktrail」／「啟動 Worktrail」捷徑 | — |
| 「啟動」資料夾（Windows）／LaunchAgent（macOS） | 開機自動啟動服務（預設開啟，可在設定 → 整合關閉） | — |

你原本的其他 hook、權限、指令與 CLAUDE.md 內容都會保留。重複執行一鍵安裝不會產生重複設定。

### 第一次開啟：引導頁

第一次開啟 Worktrail 會先出現引導頁，四個步驟都有預設值，直接按「下一步」也可以：

| 步驟 | 設定 |
| --- | --- |
| 1. 你是誰 | 名字（週報與績效中的稱呼）、每日工時 |
| 2. Jira 代碼 | 從近 7 天的對話紀錄偵測單號代碼（例如 `BMS-12` 的 `BMS`），預先勾選；也可以手動加入。不用 Jira 就全部取消勾選 |
| 3. 報告週期 | 週報起始日、每週或雙週，績效週期與考核年度起始月；下方即時顯示本期週報與績效的範圍 |
| 4. 外觀與完成 | 淺色／深色、簡約／筆記本，點選即套用；環境檢查（claude CLI、hook、MCP 等）有問題時列出修復方式 |

每一步按「下一步」就存檔；按「稍後再設定」直接進入主畫面。之後可在 設定 → 一般 →「重新執行引導」再走一次。已在使用的人更新後不會出現引導頁。

引導頁沒有包含的設定：**專案對應規則**（例如工作目錄 `C:/proj/se-*` 對應到「社交工程」），在 設定 → 專案 新增；沒有設定時，專案名稱會是資料夾名稱。

## 4. 啟動與日常使用

開啟 Worktrail 視窗的方式（擇一）：

- 雙擊專案資料夾內的 **「啟動 Worktrail」**
- 桌面或開始功能表的 **「Worktrail」**（可釘選到工作列）
- 在 Claude Code 輸入 `/worklog-ui`

關閉視窗不會停止服務，自動記錄與每日補漏掃描會繼續運作。要停止服務：設定 → 整合 →「停止服務」。

## 5. 更新

取得新版程式（例如覆蓋專案資料夾）後，再執行一次 **`一鍵安裝`**。設定與日誌都會保留，hook 與指令會更新成最新版本。

> 服務還在跑舊版程式時，一鍵安裝會自動重新啟動它；之後點「啟動 Worktrail」捷徑時也會檢查，不需要手動重啟。

## 6. 搬移專案資料夾

hook 與 MCP 設定記錄的是專案資料夾的絕對路徑。搬移專案資料夾後：

1. 在新位置執行 **`一鍵安裝`**（舊的設定會被自動辨識並取代）。
2. 舊位置若還在，可以直接刪除。

要搬移的是**日誌資料夾**（不是專案資料夾）的話，請用 設定 → 儲存 →「更換」，可選擇搬移現有資料或只改指向。

## 7. 一鍵解除安裝

1. 雙擊專案資料夾內的 **`一鍵解除安裝.cmd`**（macOS：`一鍵解除安裝.command`）。
2. 確認畫面會列出將移除與保留的項目，輸入 `y` 確定。
3. 完成後開啟新的 Claude Code 對話，設定變更才會生效。

| 會移除 | 會保留 |
| --- | --- |
| settings.json 中 Worktrail 的 3 個 hook 與權限 | 你的其他 hook 與權限 |
| MCP Server 註冊 | — |
| 4 個 `/worklog` 指令檔 | 你自己的指令檔 |
| CLAUDE.md 中 Worktrail 的規則區塊 | CLAUDE.md 的其他內容 |
| 捷徑、開機自動啟動、常駐服務 | — |
| `~/.worktrail/` 中的指標檔 | — |
| — | **所有日誌、週報、績效、範本與設定（日誌資料夾）** |
| — | Node.js、Claude Code、專案資料夾 |

之後想恢復使用，再執行一鍵安裝並選擇同一個日誌資料夾，就能接續原本的紀錄。

### 連日誌一起刪除

一鍵解除安裝**不會**刪除日誌。確定不再需要時：

```bash
node dist/cli.cjs uninstall --purge
```

會再次確認後才刪除整個日誌資料夾，無法復原。也可以直接手動刪除日誌資料夾。

### 還原安裝前的 settings.json

解除安裝是依標記精準移除，通常不需要還原備份。若仍想回到安裝前的狀態，`~/.claude/` 中最早的 `settings.json.worktrail-backup-<時間>` 就是安裝前的版本，將它改名為 `settings.json` 即可（會失去安裝後你自己做的其他修改）。

## 8. 疑難排解

先在專案資料夾開啟終端機執行：

```bash
node dist/cli.cjs doctor
```

會逐項列出安裝狀態與修復建議。設定 → 整合 也有相同的檢查結果與最近的錯誤紀錄。

| 狀況 | 處理方式 |
| --- | --- |
| Claude Code 對話結束後沒有出現紀錄 | 確認是在**安裝後開的新對話**；執行 doctor 檢查 hook；活躍時間低於 5 分鐘且沒有 commit 的對話不會建立任務（可在設定 → 記錄調整）；到設定 → 整合按「立即掃描」 |
| 點捷徑後 10 秒沒有開啟、出現錯誤視窗 | 按錯誤視窗的「是」執行診斷；常見原因是埠號 4870 被占用（修改日誌資料夾中 `config.yaml` 的 `ui.port`） |
| 「補寫摘要」或「產生」失敗：找不到 claude CLI | 執行一鍵安裝補裝 Claude Code，或在設定 → 整合指定 `claude` 的路徑後按「測試」 |
| 「產生」失敗：未登入 | 在終端機執行 `claude auth login` 完成登入；設定 → 整合的「已登入 Claude 帳號」會顯示目前狀態 |
| 一鍵安裝出現「無法載入，因為這個系統上已停用指令碼執行」 | 一鍵安裝已使用 `-ExecutionPolicy Bypass`；若公司政策仍阻擋，請改在終端機依序執行第 9 節的手動指令 |
| Node.js 安裝後仍顯示找不到 | 關閉安裝視窗，重新雙擊一鍵安裝（新視窗才會讀到新的 PATH） |
| Claude 一直被要求「先更新日誌」 | 這是摘要把關：有新 commit 但日誌未更新時會提醒一次。可在設定 → 記錄將「摘要把關」改為關閉 |

執行紀錄位於 `<日誌資料夾>\.worktrail\logs\`，保留 14 天。

## 9. 手動指令對照

一鍵腳本做的事情，也可以在專案資料夾的終端機中逐步執行：

```bash
npm install
npm run build
npm run build:launcher
node dist/cli.cjs install
```

| 指令 | 用途 |
| --- | --- |
| `node dist/cli.cjs install [--storage <資料夾>] [--yes] [--autostart]` | 安裝 |
| `node dist/cli.cjs uninstall [--purge]` | 解除安裝（`--purge` 連日誌一起刪除） |
| `node dist/cli.cjs doctor` | 檢查安裝狀態 |
| `node dist/cli.cjs open`／`stop` | 開啟 Worktrail（服務未執行或是舊版時自動啟動）／停止服務 |
| `node dist/cli.cjs sweep` | 立即補漏掃描 |
